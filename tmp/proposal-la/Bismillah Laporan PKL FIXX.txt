PENDAHULUAN
Latar Belakang
Politeknik Negeri Malang merupakan salah satu perguruan tinggi vokasi negeri terkemuka di Jawa Timur yang berkomitmen mencetak lulusan siap kerja melalui pembelajaran berbasis kompetensi dan praktik industri. Program Studi D3 Manajemen Informatika PSDKU Politeknik Negeri Malang di Kota Kediri hadir sebagai perpanjangan akses pendidikan vokasi bidang teknologi informasi bagi masyarakat di wilayah Kediri dan sekitarnya, dengan membekali mahasiswa kompetensi teknis di bidang pengembangan maupun pengujian perangkat lunak (software testing) agar siap terjun langsung ke dunia industri (Tim Penyusun, 2021).
Perkembangan pesat media sosial sebagai instrumen utama pemasaran digital telah mengubah paradigma komunikasi bisnis secara fundamental. Platform-platform seperti Instagram, TikTok, dan Facebook kini bukan sekadar sarana interaksi sosial, melainkan menjadi channel strategis bagi perusahaan untuk membangun brand awareness, menjangkau target pasar yang lebih luas, dan mendorong konversi penjualan secara terukur. Bagi perusahaan yang mengelola banyak merek dagang (multi-brand) secara simultan, kompleksitas produksi konten meningkat secara eksponensial mulai dari ideasi, desain visual, penulisan caption, proses persetujuan berjenjang, hingga penjadwalan dan publikasi ke berbagai platform.
PT. Elecomp Indonesia, sebagai perusahaan yang bergerak di bidang pengembangan perangkat lunak, digital marketing, dan manajemen media sosial, menghadapi tantangan operasional serupa. Dengan portofolio beberapa brand bisnis aktif yang masing-masing memerlukan strategi konten tersendiri, tim kreatif perusahaan menghadapi beberapa permasalahan krusial:
Alur Persetujuan (Approval) Belum Terstandarisasi: Pengajuan ide, revisi desain, penulisan caption, hingga persetujuan akhir dari Manajer masih dilakukan melalui aplikasi pesan instan grup chat dan spreadsheet terpisah. Hal ini menyebabkan risiko terlewatnya revisi (human error) dan ketidakjelasan status pengerjaan konten.
Ketiadaan Pemisahan Hak Akses (Role-Based Access Control): Belum terdapat pembatasan wewenang yang tegas antara Manajer, Tim Kreatif, Desainer (Content Creator), dan Admin Media Sosial. Siapa pun dapat mengubah data tanpa validasi otorisasi, sehingga rentan terhadap kesalahan modifikasi konten.
Absennya Pencatatan Jejak Audit (Audit Trail): Tidak ada sistem pencatatan otomatis yang merekam siapa melakukan perubahan apa, kapan, dan mengapa sehingga akuntabilitas dan transparansi dalam proses produksi konten sulit dijamin.
Isolasi Data Antar Bisnis yang Lemah: Konten, aset desain, dan jadwal tayang dari beberapa brand yang berbeda tercampur dalam satu dokumen kerja yang sama, meningkatkan potensi kebocoran informasi dan kesalahan cross-posting.
Untuk mengatasi permasalahan tersebut, dibutuhkan sebuah solusi perangkat lunak terpadu melalui "Rancang Bangun Sistem Manajemen Konten Media Sosial Berbasis Web dengan Approval Workflow dan Role-Based Access Control pada PT. Elecomp Indonesia". Sistem ini dikembangkan menggunakan framework CodeIgniter 4 berbasis arsitektur MVC (Model-View-Controller) dan database MySQL, dengan menerapkan mesin status (state machine) 8 tahapan approval yang ketat serta pemisahan peran 6 role pengguna (Superadmin, Owner, Manager, Creative Team, Content Creator, dan Admin Media Sosial). Sistem ini juga dilengkapi fitur pencatatan audit trail otomatis, notifikasi in-app, manajemen multi-bisnis dengan Business Switcher, kalender jadwal tayang, serta modul pendukung kreatif terintegrasi.
Tujuan
 Adapun tujuan dilaksanakannya Praktik Kerja Lapangan dan pembangunan sistem ini adalah:
Memenuhi salah satu kurikulum wajib Program Studi DIII Manajemen Informatika PSDKU Politeknik Negeri Malang di Kota Kediri.
Menerapkan kompetensi analisis, perancangan, pemrograman web (MVC), dan basis data pada permasalahan operasional nyata di industri.
Merancang dan mengimplementasikan arsitektur State Machine pada sistem persetujuan konten (approval workflow) dengan delapan status kerja yang tervalidasi.
Menerapkan model keamanan Role-Based Access Control (RBAC) pada enam tingkatan peran pengguna guna menjamin integritas data dan pemisahan tugas (separation of duties).
Mengintegrasikan Google Gemini API sebagai asisten pembuatan ide/caption dan Meta Graph API untuk publikasi otomatis konten media sosial.

Masalah
Selama pelaksanaan PKL, penulis menghadapi beberapa masalah, antara lain:
Penulis belum memiliki pengalaman dalam mengimplementasikan alur persetujuan bertingkat dengan aturan transisi status yang ketat, termasuk validasi peran pengguna dan pencatatan audit trail pada setiap perubahan status.
Penulis belum pernah mengintegrasikan layanan API eksternal (Google Gemini API dan Meta Graph API) ke dalam aplikasi web berbasis CodeIgniter 4, termasuk penanganan autentikasi token, pengelolaan kredensial terenkripsi, dan mekanisme fallback saat terjadi kegagalan koneksi.

Penanganan
 	Penanganan terhadap masalah-masalah tersebut adalah sebagai berikut:
Penulis mempelajari konsep finite state machine dan mengimplementasikannya melalui class TransisiKonten yang berfungsi sebagai service terpusat. Setiap transisi status divalidasi berdasarkan tiga aspek: 
Apakah transisi dari status lama ke status baru valid,
Apakah peran pengguna diizinkan untuk melakukan transisi tersebut,
Apakah catatan wajib sudah diisi untuk transisi tertentu. Pendekatan ini dipelajari secara mandiri melalui dokumentasi resmi dan referensi teknis di internet.
Penulis mempelajari dokumentasi resmi Google Gemini API dan Meta Graph API, kemudian mengimplementasikan service layer terpisah (AiService dan GraphApiService) dengan mekanisme fallback tiga tingkat (cURL → PHP Stream → SSL Socket) untuk memastikan kompatibilitas dengan berbagai konfigurasi hosting. Penulis juga membangun logika retry otomatis untuk menangani kegagalan sementara pada API.
Penulis merancang mekanisme Business Switcher yang menyimpan bisnis_aktif_id dalam session pengguna. Setiap query pada model dan controller difilter berdasarkan bisnis aktif menggunakan kolom bisnis_id sebagai foreign key pada tabel-tabel terkait (content_plan, platforms, jenis_konten, content_types, trend_bank, brand_assets).
Penulis mempelajari penggunaan library Encrypter bawaan CodeIgniter 4 untuk mengenkripsi dan mendekripsi kredensial API menggunakan algoritma AES-256. Kredensial disimpan dalam format hex-encoded di basis data dan didekripsi saat runtime menggunakan kunci enkripsi yang dikonfigurasi di file .env.
 Sistem Manajemen Konten Media Sosial Berbasis Web Dengan Approval Workflow Dan Role-Based Access Control Studi Kasus PT. ELECOMP INDONESIA
Pengembangan sistem ini termasuk dalam kategori pembangunan dan perancangan aplikasi sistem informasi berbasis web dengan pendekatan berorientasi objek (Object-Oriented). Kontribusi pengembangan sistem dijabarkan secara sistematis dan berkaidah ilmiah mengikuti tahapan siklus pengembangan perangkat lunak (Software Development Life Cycle - SDLC) yang mencakup:
Menganalisis permasalahan operasional, pemecahan masalah yang diusulkan, serta identifikasi kebutuhan fungsional dan non-fungsional sistem.
Memodelkan sistem menggunakan kerangka Unified Modeling Language (UML) yang terdiri dari Use Case Diagram, Activity Diagram, State Machine Diagram, matriks Role-Based Access Control (RBAC), Entity Relationship Diagram (ERD), dan Arsitektur MVC.
Menjelaskan realisasi rancangan ke dalam bentuk kode program, struktur data, antarmuka pengguna (User Interface), layanan logika bisnis (Service Layer), serta integrasi antarmuka eksternal (Google Gemini API dan Meta Graph API).
Melakukan pengujian fungsionalitas perangkat lunak secara menyeluruh menggunakan metode Black Box Testing untuk memvalidasi kesesuaian sistem terhadap kebutuhan yang telah ditentukan.
Analisis Sistem 
Tahap analisis sistem merupakan langkah awal yang krusial dalam rekayasa perangkat lunak untuk mengidentifikasi akar permasalahan pada alur kerja operasional tim media sosial eksisting, merumuskan solusi berbasis teknologi informasi, serta mendefinisikan spesifikasi kebutuhan sistem secara terperinci.
Analisis Permasalahan
Sebelum Sistem Manajemen Media Sosial (SMMS) dikembangkan, pengelolaan konten media sosial di PT. Elecomp Indonesia Group menghadapi beberapa permasalahan sebagai berikut:
Proses produksi konten dari ide hingga publikasi tidak memiliki tahapan persetujuan yang jelas. Konten dapat dipublikasikan tanpa melalui proses review oleh manager, sehingga berpotensi menurunkan kualitas konten yang dipublikasikan.
Tidak terdapat mekanisme pencatatan riwayat perubahan status konten. Tim kesulitan mengetahui pada tahap mana suatu konten berada, siapa yang melakukan perubahan terakhir, serta alasan di balik penolakan atau permintaan revisi.
Pembagian tugas antara content creator, designer, dan admin media sosial dilakukan secara manual melalui pesan, sehingga sering terjadi tumpang tindih atau kelalaian tugas.
Perusahaan mengelola beberapa akun media sosial untuk klien/bisnis yang berbeda, namun tidak memiliki sistem yang mampu mengisolasi data antar bisnis secara terpisah.
Proses pengunggahan konten ke platform media sosial (Instagram) dilakukan secara manual satu per satu, tanpa fitur penjadwalan otomatis.
Analisis Pemecahan Masalah
Berdasarkan analisis permasalahan di atas, dikembangkan Sistem Manajemen Media Sosial (SMMS) dengan solusi sebagai berikut:
Siklus hidup konten dikendalikan oleh 8 status tetap (ide_diajukan, acc_ide, in_design, review_design, acc_final, published, serta revisi dan ditolak sebagai status cabang) dengan aturan transisi yang hanya dapat dieksekusi oleh role tertentu.
Setiap perubahan status konten dicatat secara otomatis di tabel content_status_log, termasuk informasi pelaku, status sebelum dan sesudah, catatan revisi/penolakan, serta waktu perubahan. Hal ini memungkinkan pelacakan riwayat konten secara lengkap.
Sistem menerapkan Role-Based Access Control dengan enam peran pengguna yang masing-masing memiliki hak akses dan tanggung jawab yang jelas. Fitur notifikasi in-app juga diimplementasikan untuk memberitahu pengguna terkait secara otomatis saat terjadi perubahan status konten.
Sistem mendukung pengelolaan hingga 10 bisnis secara terisolasi. Setiap bisnis memiliki data platform, jenis konten, content pillar, konten, bank tren, dan aset brand tersendiri. Pengguna dapat berpindah bisnis aktif melalui Business Switcher tanpa harus logout.
Sistem terintegrasi dengan Meta Graph API v26.0 untuk publikasi konten ke Instagram (foto, video/reels, carousel, story). Fitur penjadwalan otomatis (auto-publish) memungkinkan konten dipublikasikan secara otomatis sesuai jadwal yang telah ditentukan.
Analisis Kebutuhan Fungsional dan Non-Fungsional
Tahap analisis kebutuhan bertujuan untuk mengidentifikasi kebutuhan fungsional serta kebutuhan nonfungsional, dengan rincian sebagai berikut.

Kebutuhan fungsional adalah kebutuhan yang berkaitan dengan fungsi utama sistem, mencakup fitur dan layanan yang harus tersedia untuk mendukung pengguna. Kebutuhan ini menjelaskan respons sistem terhadap input serta bagaimana sistem beroperasi pada situasi tertentu. Activity Diagram
Activity Diagram digunakan untuk menggambarkan aliran kerja (workflow) dan urutan aktivitas operasional dalam sistem dari status awal, percabangan keputusan, hingga status akhir. Autentikasi Pengguna (Login)
Activity Diagram autentikasi pengguna memodelkan alur proses masuk (login) pengguna ke dalam sistem SMMS. Alur dimulai ketika pengguna mengakses halaman login, mengisikan alamat email dan kata sandi, lalu menekan tombol masuk; sistem SMMS selanjutnya memvalidasi kelengkapan format masukan, di mana jika format tidak valid maka sistem memunculkan notifikasi validasi ke layar, sedangkan jika format valid sistem melanjutkan verifikasi kredensial serta pencocokan enkripsi kata sandi ke basis data. Apabila kredensial tidak cocok, sistem menampilkan pesan kesalahan login dan mengembalikan pengguna ke form input, namun jika kredensial terbukti valid, sistem langsung menginisialisasi sesi login (session), menetapkan hak akses peran pengguna, serta mengarahkan tampilan secara otomatis ke dashboard utama sesuai dengan peran pengguna yang bersangkutan.

Pengujian Sistem
 Pengujian sistem merupakan tahapan krusial dalam siklus pengembangan perangkat lunak untuk memastikan bahwa seluruh modul dan fungsionalitas yang telah diimplementasikan bekerja sesuai dengan spesifikasi kebutuhan yang telah ditetapkan pada tahap analisis. Pengujian ini bertujuan untuk memverifikasi keandalan sistem, mendeteksi potensi kesalahan (bug) atau celah logika bisnis, serta menjamin bahwa aplikasi bebas dari kegagalan operasional saat digunakan oleh pengguna akhir.
Metode pengujian yang digunakan dalam penelitian ini adalah metode Black Box Testing (pengujian kotak hitam). Metode Black Box Testing berfokus pada pengujian fungsionalitas perangkat lunak dari sudut pandang pengguna tanpa perlu mengetahui atau menguji struktur kode program internal secara langsung. Pengujian dilakukan dengan memberikan serangkaian masukan (input) tertentu ke antarmuka sistem, memprosesnya melalui fungsi aplikasi, dan mengamati apakah keluaran (output) atau respons sistem yang dihasilkan telah sesuai dengan hasil yang diharapkan (expected result).
Cakupan pengujian fungsionalitas Sistem Manajemen Media Sosial (SMMS) ini mencakup seluruh modul utama, meliputi mekanisme autentikasi dan otorisasi Role-Based Access Control (RBAC), isolasi data multi-bisnis (Business Switcher), alur kerja persetujuan berbasis state machine 8 status, integrasi eksternal Meta Graph API v26.0 dan Google Gemini API, fitur otomatisasi penayangan (auto-publish), pencatatan jejak audit (audit trail), hingga rekapitulasi data laporan. Hasil pengujian fungsionalitas sistem secara rinci disajikan pada Tabel 2.5.
Tabel 2.5 Hasil Pengujian Fungsionalitas Sistem 

Berdasarkan hasil pengujian fungsionalitas yang terangkum pada Tabel 2.5, seluruh 20 (dua puluh) butir skenario pengujian yang mencakup proses autentikasi, manajemen hak akses, alur persetujuan state machine, integrasi API pihak ketiga, hingga pelaporan menunjukkan hasil yang sesuai dengan hasil yang diharapkan (expected result = actual result). Dengan demikian, diperoleh tingkat keberhasilan pengujian fungsionalitas sebesar 100% dengan kesimpulan Valid. Hasil ini membuktikan bahwa Sistem Manajemen Media Sosial (SMMS) telah memenuhi seluruh spesifikasi kebutuhan fungsional maupun non-fungsional yang telah dirancang, memiliki stabilitas alur kerja yang baik, dan layak untuk diimplementasikan dalam menunjang operasional digital di PT. Elecomp Indonesia Group.

SIMPULAN DAN SARAN
3.1. Simpulan
Berdasarkan pelaksanaan Praktik Kerja Lapangan (PKL) di PT. Elecomp Indonesia Group serta merujuk pada lima tujuan yang telah dirumuskan pada BAB I, dapat ditarik simpulan sebagai berikut:
1. Terkait pemenuhan kurikulum wajib Program Studi DIII Manajemen Informatika PSDKU Politeknik Negeri Malang di Kota Kediri, penulis telah berhasil menyelesaikan seluruh rangkaian kegiatan Praktik Kerja Lapangan (PKL) di PT. Elecomp Indonesia Group serta menyusun laporan pertanggungjawaban ilmiah ini sesuai dengan kaidah akademik dan standar kompetensi yang ditetapkan.
2. Terkait penerapan kompetensi analisis, perancangan, pemrograman web (MVC), dan basis data pada permasalahan operasional nyata di industri, penulis telah berhasil menganalisis proses bisnis pengelolaan konten media sosial, memodelkannya ke dalam diagram UML (Use Case Diagram dan Activity Diagram), membangun arsitektur MVC menggunakan framework CodeIgniter 4, serta merancang basis data relasional MySQL yang terdiri dari 15 tabel terintegrasi. Sistem telah diuji menggunakan metode Black Box Testing dengan 20 butir skenario pengujian fungsional dan menghasilkan tingkat keberhasilan 100% (Valid).
3. Terkait perancangan dan implementasi arsitektur State Machine pada sistem persetujuan konten (approval workflow), sistem telah berhasil merealisasikan mesin status dengan delapan tahapan kerja yang tervalidasi (ide_diajukan, acc_ide, in_design, review_design, revisi, acc_final, published, dan ditolak). Mekanisme ini berhasil mendisiplinkan alur produksi konten secara bertahap, mencegah terjadinya kesalahan publikasi konten yang belum disetujui manajer, serta memastikan setiap perubahan terekam secara kronologis pada tabel log jejak audit (audit trail).
4. Terkait penerapan model keamanan Role-Based Access Control (RBAC) pada enam tingkatan peran pengguna, sistem telah berhasil membatasi wewenang dan hak akses secara presisi pada setiap peran (Superadmin, Owner, Manager, Creative Team, Content Creator, dan Admin Media Sosial). Penerapan RBAC ini berhasil mewujudkan prinsip pemisahan tugas (separation of duties), melindungi kredensial integrasi API, serta mendukung operasional banyak unit bisnis (multi-tenancy) secara aman dan terisolasi melalui fitur Business Switcher.
5. Terkait integrasi layanan pihak ketiga, sistem telah berhasil mengintegrasikan Google Gemini API sebagai asisten cerdas dalam pembuatan ide konten, draf takarir (caption), hook generator, dan evaluasi kesesuaian konten pra-review. Selain itu, sistem berhasil mengintegrasikan Meta Graph API v26.0 untuk penayangan langsung maupun penjadwalan penerbitan otomatis (auto-publish) konten gambar, carousel, reels, dan story ke akun Instagram Bisnis dengan pencatatan log transaksi jaringan secara terpusat pada tabel meta_api_logs.
3.2. Saran
Berdasarkan simpulan yang diperoleh dari hasil analisis, perancangan, implementasi, dan pengujian Sistem Manajemen Media Sosial (SMMS), penulis menyampaikan beberapa saran yang diharapkan dapat menjadi masukan konstruktif untuk pengembangan sistem lebih lanjut di masa mendatang:
1. Pengembangan Notifikasi Eksternal Berbasis Real-Time: Sistem saat ini baru menyediakan notifikasi internal di dalam aplikasi (in-app notification). Untuk meningkatkan responsivitas tim kerja, disarankan untuk mengintegrasikan protokol WebSocket atau layanan pesan instan pihak ketiga (seperti WhatsApp Business Cloud API atau Telegram Bot) agar notifikasi penugasan baru atau instruksi revisi mendesak dapat diterima secara langsung pada perangkat pengguna.
2. Perluasan Integrasi Multi-Platform Media Sosial: Saat ini fitur penerbitan otomatis (auto-publish) baru terintegrasi secara penuh ke akun Instagram melalui Meta Graph API. Disarankan untuk memperluas konektivitas API resmi ke platform media sosial populer lainnya seperti TikTok (TikTok Content Posting API) dan YouTube (YouTube Data API v3) guna memfasilitasi publikasi konten lintas platform dalam satu langkah.
3. Pengembangan Modul Analisis Performa Konten Pasca-Tayang (Insights Analytics): Disarankan untuk menambahkan modul analitik performa yang mampu menarik data statistik (seperti reach, impressions, engagement rate, likes, dan shares) dari platform media sosial secara berkala. Data analitik ini dapat dimanfaatkan oleh manajemen untuk mengevaluasi efektivitas strategi konten pemasaran pada setiap unit bisnis.

public function store(): \CodeIgniter\HTTP\ResponseInterface
{
    $userId   = (int) session('user_id');
    $kodeRole = session('kode_role');

    if (in_array($kodeRole, ['admin_medsos'], true)) {
        return $this->jsonGagal('Anda tidak memiliki akses untuk membuat ide konten.', 403);
    }

    $db = \Config\Database::connect();


    $assignedDesigner = $this->request->getPost('assigned_designer') ?: null;
    $assignedUploader = $this->request->getPost('assigned_uploader') ?: null;

    $rawTgl = $this->request->getPost('tanggal_publish');
    $tglPublish = $rawTgl ? date('Y-m-d H:i:s', strtotime(str_replace('T', ' ', $rawTgl))) : null;

    $data = [
        'bisnis_id'         => (int) session('bisnis_aktif_id'),
        'judul_konten'      => $this->request->getPost('judul_konten'),
        'deskripsi'         => $this->request->getPost('deskripsi'),
        'tanggal_publish'   => $tglPublish,
        'jenis_konten_id'   => $this->request->getPost('jenis_konten_id') ?: null,
        'content_type_id'   => $this->request->getPost('content_type_id') ?: null,
        'assigned_designer' => $assignedDesigner,
        'assigned_uploader' => $assignedUploader,
    ];

    $contentId = $this->model->buatIde($data, $userId);
    if (!$contentId) {
        return $this->jsonGagal('Validasi gagal: ' . implode(', ', $this->model->errors()), 422);
    }

    $platforms = $this->request->getPost('platforms') ?? [];
    if (!empty($platforms)) {
        foreach ($platforms as $platId) {
            $db->table('content_platforms')->insert([
                'content_id'  => $contentId,
                'platform_id' => (int) $platId,
            ]);
        }
    }

    $logModel = new \App\Models\ContentStatusLogModel();
    $logModel->insert([
        'content_id'  => $contentId,
        'status_lama' => null,
        'status_baru' => 'ide_diajukan',
        'user_id'     => $userId,
        'catatan'     => 'Ide baru diajukan ke sistem.',
    ]);

    return $this->jsonSukses('Ide konten berhasil dibuat.', ['id' => $contentId], 201);
}
class TransisiKonten
{
    private const TRANSISI_VALID = [
        'ide_diajukan' => [
            'acc_ide'  => ['roles' => ['manager'], 'catatan_wajib' => false],
            'revisi'   => ['roles' => ['manager'], 'catatan_wajib' => true],
            'ditolak'  => ['roles' => ['manager'], 'catatan_wajib' => true],
        ],
        'revisi' => [
            'ide_diajukan' => ['roles' => ['creative_team', 'content_creator'], 'catatan_wajib' => false],
        ],
        'acc_ide' => [
            'in_design' => ['roles' => ['content_creator'], 'catatan_wajib' => false],
        ],
        'in_design' => [
            'review_design' => ['roles' => ['content_creator'], 'catatan_wajib' => false],
        ],
        'review_design' => [
            'acc_final' => ['roles' => ['manager'], 'catatan_wajib' => false],
            'revisi'    => ['roles' => ['manager'], 'catatan_wajib' => true],
        ],
        'acc_final' => [
            'published' => ['roles' => ['admin_medsos'], 'catatan_wajib' => false],
        ],
    ];

    public function transition(int $contentId, string $statusBaru, int $userId, string $catatan = ''): array
    {
        $konten = $this->contentPlanModel->find($contentId);
        $statusLama = $konten['status'];

        // 1. Validasi Matriks Aturan Transisi
        $aturan = self::TRANSISI_VALID[$statusLama][$statusBaru] ?? null;
        if (!$aturan) {
            return ['sukses' => false, 'pesan' => "Transisi dari {$statusLama} ke {$statusBaru} tidak diizinkan."];
        }

        if ($aturan['catatan_wajib'] && empty(trim($catatan))) {
            return ['sukses' => false, 'pesan' => 'Catatan arahan wajib diisi untuk tindakan ini.'];
        }

        $this->contentPlanModel->update($contentId, ['status' => $statusBaru]);

        $this->statusLogModel->insert([
            'content_id'  => $contentId,
            'status_lama' => $statusLama,
            'status_baru' => $statusBaru,
            'user_id'     => $userId,
            'catatan'     => $catatan,
            'created_at'  => date('Y-m-d H:i:s'),
        ]);

        return ['sukses' => true, 'pesan' => "Status berhasil diperbarui menjadi {$statusBaru}."];
    }
}
public function store(): \CodeIgniter\HTTP\ResponseInterface
{
    $role = session('kode_role');
    if (!in_array($role, ['superadmin', 'owner'], true)) {
        return $this->jsonGagal('Akses ditolak. Khusus Superadmin dan Owner.', 403);
    }

    $encrypter   = \Config\Services::encrypter();
    $secretPlain = trim($this->request->getPost('meta_app_secret') ?? '');
    $tokenPlain  = trim($this->request->getPost('meta_access_token') ?? '');
    $geminiPlain = trim($this->request->getPost('gemini_api_key') ?? '');

    $secretEnc = !empty($secretPlain) ? bin2hex($encrypter->encrypt($secretPlain)) : null;
    $tokenEnc  = !empty($tokenPlain)  ? bin2hex($encrypter->encrypt($tokenPlain))  : null;
    $geminiEnc = !empty($geminiPlain) ? bin2hex($encrypter->encrypt($geminiPlain)) : null;

    $data = [
        'nama_bisnis'        => trim($this->request->getPost('nama_bisnis')),
        'deskripsi'          => trim($this->request->getPost('deskripsi')),
        'warna'              => $this->request->getPost('warna') ?: '#6C5CE7',
        'logo_url'           => $this->request->getPost('logo_url') ?: null,
        'status'             => 'aktif',
        'meta_app_id'        => trim($this->request->getPost('meta_app_id')) ?: null,
        'meta_app_secret'    => $secretEnc,
        'meta_access_token'  => $tokenEnc,
        'meta_ig_account_id' => trim($this->request->getPost('meta_ig_account_id')) ?: null,
        'meta_ig_username'   => trim($this->request->getPost('meta_ig_username')) ?: null,
        'gemini_api_key'     => $geminiEnc,
    ];

    if (!$this->bisnisModel->insert($data)) {
        return $this->jsonGagal('Gagal menyimpan bisnis: ' . implode(', ', $this->bisnisModel->errors()), 422);
    }

    $newId = (int) $this->bisnisModel->getInsertID();
    return $this->jsonSukses('Bisnis baru berhasil ditambahkan.', ['id' => $newId], 201);
}
